## Confirmed findings and remediations

| Finding | Preconditions and impact | Evidence and response |
| --- | --- | --- |
| Server environment reaches executable tools/stdio MCP (high, conditional) | An enabled or compromised child receives any server OAuth/provider/database secrets in the inherited environment. Tool execution must first be permitted. | `internal/security/executor.go` used `os.Environ`; `internal/mcp/client_sdk.go` also inherited all variables, implicitly when env was nil. Both now use `internal/childenv`. Real subprocess tests prove synthetic server secrets are absent while configured tool credentials and explicitly allowlisted variables remain available. |
| Fabricated authorization/unbounded instructions (high, conditional) | Bundled prompts/skills could treat scope expansion as approved, continue indefinitely, or use public intermediaries automatically. Native RBAC was not bypassed by the text alone. | Main/planner/supervisor and every agent/role/skill instruction were manually reviewed/re-authored. They bind actions to trusted engagement scope and existing approvals, preserve authorized autonomy, honor actual guards/stop criteria and distinguish evidence from authority. Untrusted WebShell metadata is JSON-quoted and labeled. No live model-behavior acceptance was run. |
| Explicitly disabled exec dispatch bypass (high, conditional) | The special exec dispatch preceded configured enablement checks, so an explicitly disabled exec entry could still launch a shell if reached through that executor. | `internal/security/executor.go` now rejects explicitly disabled exec before dispatch. An actual executable-boundary test verifies no child launches for disabled exec or DNSlog, with an enabled harmless child as a positive control. Stable tool IDs and the absent-config built-in behavior remain. |
| Public plaintext OAST/session storage (medium/high, conditional) | The default-enabled dnslog recipe used HTTP dnslog.cn, sending callback/session traffic to a public third party, and shared a predictable temporary cookie file. | `tools/dnslog.yaml` is disabled by default and requires an explicit operator enablement decision. It supports an operator-configured HTTP(S) DNSLOG_BASE_URL; authorized HTTPS/self-hosted OAST is preferred. Per-domain session files are private and separate, with no-follow/exclusive creation and POSIX owner/type/mode checks. A fake requests-module fixture proves session separation without network calls. The historical public HTTP default remains insecure when deliberately enabled. |
| Vendor updater could replace fork protections (high operational risk) | With source unset, accepting a vendor update could replace the maintained SSO/language/security chain. This was intentional upstream behavior, not proof of malicious updates. | `internal/update/update.go` and `upgrade.sh` now default to the fork. Explicit overrides remain visible trust decisions. Vendor updates require a reviewed merge PR; the scheduled disposable merge check never promotes or deploys. |
| Implicit mirrors/floating Python installation (medium) | Installation executes packages from selected registries and lower-bound requirements can resolve different future code. | `run.sh` defaults to official PyPI/Go registries and reports the Go minimum from go.mod. Explicit operator overrides still work. Python installation locking/artifact verification remains unresolved; lower-bound requirements do not establish reproducible deployment. |
| Vulnerable module/toolchain baseline | Advisory presence does not by itself demonstrate exploitation, but reachable image/protocol paths require remediation. | Pinned Go 1.26.10, MCP SDK 1.4.1, gRPC 1.83.2, x/image 0.45.0 and compatible transitive upgrades replace the affected baseline. Final native Linux analysis and checksums are described below; the OpenPGP advisory remains explicit. |
| Catalog migration destination overwrite race | An operator edit to a renamed destination after planning could be overwritten during apply. | The migrator rechecks staged source/destination state. Renamed destinations are never replaced: reuse an exact English copy or create an absent path with an exclusive hard link. CLI-injected concurrent-edit fixtures prove custom content and the legacy source survive refusal. Migration still requires an idle installation and is atomic per file, not a transaction across the installation. |

## Execution, triggers and network paths inspected

`internal/mcp/server.go` applies the common tool authorizer to HTTP/attributed agent calls, checks tool guards and retains execution ownership. `internal/app/mcp_authorization.go` maps batch/asset/project/vulnerability/WebShell/C2 operations to native permissions and resource scopes. Configured executables use argv; the explicit exec/shell capability intentionally interprets shell syntax. Exact legacy decision/command/yes-no/role aliases are compatibility parsers only. They do not mint identities, permissions, trusted user provenance or approvals from model/target/imported/persisted text. Tests include approval-like prose, unknown roles, exact custom-role precedence, resource denial and user-scoped pending confirmations.

Child environments retain essential PATH/home/temp/system/certificate/terminal values, with LANG=C, LC_ALL=C and LANGUAGE=en_US:en. Per-MCP env values are explicit overrides. CYBERSTRIKE_CHILD_ENV_ALLOWLIST=EXACT_NAME,ANOTHER_NAME is an operator-controlled exact-name escape hatch; no wildcard/inherit-all mode exists. An allowed/configured credential is intentionally available to that child. Do not allowlist server tokens.

Batch Cron work is explicit persisted state: `internal/handler/agent.go` checks schedule mode/enabled/next-run/queue status on a 20-second loop; `batch_queue_executor.go` resolves the current owner and native RBAC per subtask, rejecting missing/disabled users. Retention loops purge configured audit/monitor/HITL/workflow-package records. MCP recovery timers reconnect configured servers. These are identified background activities; production schedules/DB records were not inspected or changed.

Native C2 is optional and privileged. Entry requires configuration plus listener/session/task APIs and native permission/resource/HITL gates. Templates include callbacks, commands, file transfer/forwarding and cron/bashrc/LaunchAgent/registry/scheduled-task persistence. tcp_reverse defaults to CSB1/AES-GCM/ImplantToken; classic unencrypted shells require explicit allow_legacy_shell. Intended pentest features are not labeled malicious merely because present. No endpoint was contacted or persistence installed during this review.

Inspected outbound construction includes configured model/embedding/rerank providers, external MCP, asset-search providers, robots, TypeSafe, Git/release downloads, OAST and optional C2. They can transmit configured prompts/results/credentials when enabled. Examples/configurations include OpenAI-compatible endpoints, Anthropic-compatible SDK providers, Cohere/DashScope, TypeSafe, WeCom/WeChat/Telegram and search providers. The optional reverse-shell helper uses a UDP route-selection socket toward 8.8.8.8 to determine a local callback address. No unrelated hardcoded exfiltration endpoint was established by this bounded source review; this is not a complete egress allowlist or proof of absence.

Configuration masking and authenticated resource checks remain. Gitleaks source scanning uses redaction; its result says nothing about production env, historical artifacts or secrets on disk. Never include actual secret values in review records.
